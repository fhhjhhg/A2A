## 2024-11-05 - Optimize Native Array Processing
**Learning:** Indiscriminately casting NumPy arrays to PyTorch tensors (e.g., `torch.as_tensor()`) just to use PyTorch-specific methods like `torch.quantile` introduces unnecessary instantiation overhead. Furthermore, `np.percentile` returns a `numpy.float64` scalar which silently promotes `float32` arrays to `float64` upon division, doubling memory consumption.
**Action:** Conditionally branch logic to use native methods (e.g., `np.percentile` for arrays, `torch.quantile` for tensors). When using `np.percentile` to calculate a scaling factor for `float32` NumPy arrays, always explicitly cast the result to a standard Python `float` (e.g., `float(np.percentile(...))`). Never cast PyTorch tensor results to Python `float` as it forces a blocking Device-to-Host (D2H) synchronization.
