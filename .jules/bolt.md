## 2023-10-25 - PyTorch Quantile Memory and Promotion Issues
**Learning:** `torch.quantile` throws a `RuntimeError` due to size limitations for `float32` tensors on large MRI volumes (> 16 million elements). While `np.percentile` handles these large structures efficiently, it returns a `numpy.float64` scalar by default. Dividing a `float32` PyTorch tensor by this scalar silently promotes the entire tensor to `float64`, doubling memory consumption and causing downstream runtime errors (`expected scalar type Float but found Double`).
**Action:** Use `np.percentile` on NumPy arrays instead of `torch.quantile` for large arrays, remembering it expects a range of [0, 100]. Always explicitly cast its result to a Python `float` (e.g., `float(np.percentile(...))`) before dividing.
