## 2024-05-23 - Optimizing NumPy and PyTorch conditional branching
**Learning:** When a utility function accepts both NumPy arrays and PyTorch tensors, casting NumPy arrays to tensors (e.g., `torch.as_tensor`) to use a generic PyTorch function introduces unnecessary instantiation overhead. Furthermore, when computing quantiles, `np.percentile` on a `float32` array returns a `numpy.float64` scalar which silently promotes the entire array to `float64` upon division, significantly increasing memory consumption.
**Action:** Conditionally branch logic to use native library methods (e.g., `np.percentile` and `np.clip` for NumPy, and `torch.quantile` and `torch.clip` for PyTorch). Always explicitly cast `np.percentile` results to a Python `float` before scaling arithmetic to maintain `float32` memory efficiency.
