## 2024-10-16 - Prevent Array Type Promotion with np.percentile
**Learning:** When using `np.percentile` to calculate a scaling factor for `float32` NumPy arrays, it defaults to returning a `numpy.float64` scalar. When the original `float32` array is divided by this scalar, it silently promotes the entire array to `float64`, doubling memory consumption. In utility functions handling both NumPy arrays and PyTorch tensors, indiscriminate conversion to PyTorch tensors (e.g., `torch.as_tensor`) simply to use `torch.quantile` introduces unnecessary instantiation overhead. Furthermore, never cast a PyTorch tensor result from a GPU to a Python float, as it detaches it from the computation graph and forces a synchronous Device-to-Host (D2H) memory transfer, stalling the GPU.
**Action:** In utility functions handling both arrays and tensors, branch logic to use native methods. For NumPy arrays, explicitly cast the scalar result of `np.percentile` to a standard Python `float` before using it in operations with the original array to avoid type promotion and memory doubling. Never force PyTorch tensors to CPU/NumPy to compute scalar metrics.
