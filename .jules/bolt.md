## 2023-11-01 - Avoid implicit GPU to CPU synchronization and unnecessary tensor instantiation
**Learning:** In utility functions handling both NumPy arrays and PyTorch tensors, indiscriminately casting NumPy arrays to PyTorch tensors (e.g., `torch.as_tensor`) to use a PyTorch-specific method introduces unnecessary tensor instantiation overhead. Furthermore, casting PyTorch tensor results (e.g. via `x.cpu().numpy()`) back to numpy indiscriminately forces a blocking Device-to-Host (D2H) synchronization if the tensor is on a GPU, stalling the GPU and causing a severe performance regression. When using `np.percentile` on NumPy arrays, the result is `numpy.float64` by default, which can silently promote the entire array to `float64` upon division, doubling memory consumption.
**Action:** Conditionally branch the logic to use native methods (e.g., `np.percentile` for arrays, `torch.quantile` for tensors) to prevent implicit conversions. Always explicitly cast `np.percentile` results to a standard Python `float` (e.g., `float(np.percentile(...))`) to avoid memory promotion when applying it to `float32` NumPy arrays. Never force a PyTorch tensor to CPU/NumPy just to compute a scalar metric.
