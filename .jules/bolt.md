## 2024-05-19 - Parallelizing large I/O bounds tasks in notebooks
**Learning:** Sequential shell downloads via `wget` and `tar` in Jupyter notebook loops (using `!`) drastically slow down data acquisition, acting as a massive I/O bottleneck. The standard shell execution magic runs each file one by one sequentially. Parallelizing the file downloads and extractions using Python's `concurrent.futures.ThreadPoolExecutor` and `subprocess` significantly speeds up the process (e.g., from ~2.0s to ~0.5s in our synthetic test, providing an estimated ~3-4x speedup).
**Action:** When notebooks have tasks to download or extract multiple large files using a loop, refactor the code to use `subprocess` and `ThreadPoolExecutor` to perform the operations concurrently. Consume the futures accurately to capture sub-process exceptions. Note: `wget` piped to `tar` requires explicit handling of OS pipe buffers (via `p1.stdout.close()` and `.communicate()`) to avoid deadlock.
