## 2025-05-11 - Avoid Unnecessary PyTorch Tensor Instantiation for NumPy Arrays
**Learning:** In utility functions handling both NumPy arrays and PyTorch tensors, conditionally branch the logic to use native methods (e.g., `np.percentile` for arrays, `torch.quantile` for tensors) rather than indiscriminately casting NumPy arrays to PyTorch tensors (e.g., `torch.as_tensor`) just to use a PyTorch-specific method, which introduces unnecessary tensor instantiation overhead and potential blocking Device-to-Host (D2H) memory transfer stalls. Furthermore, when using `np.percentile` to calculate a scaling factor for `float32` NumPy arrays, always explicitly cast the result to a standard Python `float` (e.g., `float(np.percentile(...))`). By default, `np.percentile` returns a `numpy.float64` scalar, which silently promotes the entire array to `float64` upon division, doubling memory consumption.
**Action:** When handling inputs that can be either NumPy arrays or PyTorch tensors, branch the logic to use their respective native libraries instead of forcing type conversions. Ensure proper type casting of scalars from `np.percentile` when modifying `float32` arrays to avoid unintended type promotion.
