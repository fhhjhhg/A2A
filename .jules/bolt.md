## 2025-01-20 - Parallelizing wget in Jupyter Notebooks
**Learning:** Using IPython `!` magic to run `wget` sequentially in a loop over large dataset files results in extremely slow I/O bound operations. Piping `wget` directly to `tar` using `subprocess.Popen` in a `ThreadPoolExecutor` parallelizes this, but requires careful handling: redirecting `stderr` to `subprocess.DEVNULL` to prevent deadlocks from OS pipe buffers, closing upstream `stdout` to allow `SIGPIPE`, and explicitly waiting on upstream processes before checking return codes.
**Action:** When parallelizing blocking shell commands in notebooks, use `ThreadPoolExecutor` with `subprocess.Popen/run` instead of IPython magics. Handle chained pipes carefully using the `.wait()` and `.communicate()` sequence and track progress using `concurrent.futures.as_completed(futures)` with `tqdm` to maintain UX without deadlocks.
