## 2024-05-24 - [Avoid implicit float64 promotion when scaling tensors/arrays]
**Learning:** `np.percentile` returns a `np.float64` scalar by default. When used to scale a `float32` array or tensor via division, it silently promotes the entire dataset to `float64`, doubling memory consumption and potentially causing `expected scalar type Float but found Double` runtime errors in PyTorch. Additionally, converting numpy arrays to PyTorch tensors just to compute a quantile can be less stable than using `np.percentile` natively. However, do NOT cast PyTorch tensors to Python `float` as this detaches them from the computation graph and forces blocking Device-to-Host (D2H) synchronization if the tensor is on a GPU.
**Action:** Always compute quantiles on the data's native type/device (use `np.percentile` for numpy arrays, `torch.quantile` for PyTorch tensors). Explicitly cast the scalar result of `np.percentile` to a standard Python `float` before dividing the array to prevent unexpected `float64` memory promotion. Do NOT cast the result of `torch.quantile` to `float`.
