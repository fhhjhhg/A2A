## 2026-11-07 - Avoid unnecessary D2H transfers via torch scalar operations on numpy arrays
**Learning:** Using `torch.quantile` on a `numpy.ndarray` requires implicitly casting the array to a `torch.Tensor`. When running on large arrays, if a user's environment defaults arrays to GPUs or requires host-device syncs when returning a scalar result, using PyTorch functions on numpy objects forces unnecessary synchronizations or object instantiations.
**Action:** When creating branching logic for functions handling both `torch.Tensor` and `numpy.ndarray` objects, strictly use native library implementations (for example `float(np.percentile(x, percentile * 100))` for numpy and `torch.quantile(x, percentile)` for torch tensors) to avoid type coercions, D2H memory transfer stalls, and extraneous tensor generation. Note: `np.percentile` expects a percentile out of 100, while `torch.quantile` expects a quantile between 0 and 1, and the `np.percentile` output must be explicitly cast to a standard python `float` to avoid silently promoting subsequent operations to `float64`.
