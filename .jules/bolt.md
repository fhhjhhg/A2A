## 2024-10-19 - Optimize scaling utility for mixed array/tensor types
**Learning:** In utility functions handling both NumPy arrays and PyTorch tensors, conditionally branch the logic to use native methods (e.g., `np.percentile` for arrays, `torch.quantile` for tensors) rather than indiscriminately casting NumPy arrays to PyTorch tensors (e.g., `torch.as_tensor`) just to use a PyTorch-specific method, which introduces unnecessary tensor instantiation overhead. Additionally, when using `np.percentile` to calculate a scaling factor for `float32` NumPy arrays, always explicitly cast the result to a standard Python `float` (e.g., `float(np.percentile(...))`). By default, `np.percentile` returns a `numpy.float64` scalar, which silently promotes the entire array to `float64` upon division, doubling memory consumption. However, never cast PyTorch tensor results (e.g., `torch.quantile`) to a Python `float`, as this detaches them from the computation graph and forces a blocking Device-to-Host (D2H) synchronization if the tensor is on a GPU.
**Action:** Always conditionally handle NumPy arrays using native NumPy operations instead of PyTorch casts, and ensure scalar results from `np.percentile` are cast to Python floats to prevent unwanted type promotion and memory bloat. Never detach PyTorch scalar results to Python floats.
