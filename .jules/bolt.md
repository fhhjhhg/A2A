## 2024-05-18 - [Parallelizing I/O-bound shell commands in Jupyter Notebooks]
**Learning:** Parallelizing I/O-bound shell commands (e.g., `wget`, `tar`) in Jupyter Notebooks should use `ThreadPoolExecutor` with `subprocess.run` instead of IPython `!` magic, which is not thread-safe and executes sequentially in loops. Crucially, when using `subprocess.Popen` to chain commands via pipes (e.g., piping `wget` to `tar`), explicitly call `.wait()` on the upstream process after calling `.communicate()` on the downstream process, before evaluating the upstream process's `.returncode`. This prevents race conditions where the upstream process has not fully terminated. Additionally, close the upstream process's stdout (`p1.stdout.close()`) immediately after starting the downstream process to allow it to receive a SIGPIPE and prevent deadlocks.
**Action:** When parallelizing chained I/O commands in a notebook, use `subprocess.Popen` carefully, managing standard streams to avoid deadlocks. Do not use IPython `!` magic inside python concurrent execution blocks.
