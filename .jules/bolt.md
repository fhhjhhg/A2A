## 2024-05-24 - Avoid forcing PyTorch tensors to CPU for simple quantile calculation
**Learning:** Forcing a PyTorch tensor to CPU/NumPy (e.g., `x.cpu().numpy()`) just to compute a scalar metric with `np.percentile` forces a synchronous Device-to-Host (D2H) memory transfer, stalling the GPU and causing a severe performance regression. Similarly, using `torch.quantile` on CPU/NumPy arrays by forcing them into `torch.as_tensor()` causes overhead and detaches the NumPy array from the fast path for percentile computation.
**Action:** When calculating quantiles on arrays/tensors in utility functions handling both NumPy and PyTorch objects, use native methods (e.g., `np.percentile` for numpy arrays, `torch.quantile` for torch tensors) with conditional branching logic to avoid type casting overhead. Also ensure `np.percentile` output is explicitly cast to `float()` to prevent it silently promoting array values to float64, doubling memory footprint.
